# SEO_AUDIT.md — KindredTrips repository SEO & data-integrity overhaul

Date: 2026-07-13 · Branch: `claude/complete-trip-optimization-v1YeD`

## Existing architecture

- **Framework/routing**: no framework. Static HTML site generated by a single Node script, `scripts/generate-seo-pages.mjs`, deployed on Vercel (`cleanUrls: true` — extensionless URLs serve `.html` files; `.html` requests 308-redirect to clean paths).
- **Generation**: fully static (build-time). No server rendering. Hand-maintained pages: `index.html` (search app), `about/contact/privacy`. Generated: `/resort/*`, `/caribbean*`, `/from/*`, `/compare/*`, `sitemap.xml`.
- **Data sources**: `data/resorts-seo.json` — snapshot of the Supabase `seo_resort_snapshot` view (canonical definition in `supabase/migrations/20260713_seo_resort_snapshot_view.sql`); `data/resort-review-seo.json` (guest reviews + family signals); `data/resort-liteapi-hero.json` (photos). Refreshed weekly by `.github/workflows/refresh-seo-pages.yml` via the `seo_snapshot` edge function.
- **Provider integrations**: LiteAPI (live hotel rates, hotel details, room capacities, all-inclusive rate evidence), Aviasales/Travelpayouts (flights), Booking.com (verified property deep links only). Live search runs through Supabase edge functions, client-side.
- **Search/ranking**: live search ranks by total trip cost (client). Static editorial pages rank by the family-fit score in `scripts/lib/family-rules.mjs`.
- **SEO metadata/canonicals/schema**: generated per page in the `shell()` function of the generator; JSON-LD (Resort, BreadcrumbList, CollectionPage/ItemList, FAQPage) per template.
- **Sitemap/robots/redirects**: `sitemap.xml` regenerated each build with content-hash `lastmod` (`data/lastmod.json`); `robots.txt` allows all + sitemap pointer; redirects in `vercel.json` (retired country pages → `/caribbean`) plus Vercel `cleanUrls` 308s.
- **Analytics**: GA4 (`G-4WHVMCP4Z0`) on all templates.
- **Tests/CI**: `scripts/tests/*.test.mjs` (node:test) + `scripts/validate-site.mjs` post-build crawl, enforced by `.github/workflows/ci.yml` (build-blocking).

## Problems found (this audit)

1. Homepage `<title>`/H1 didn't lead with the comparison value proposition; hero lacked the price-promise message.
2. `about/contact/privacy` canonicals and internal links pointed at `.html` URLs that Vercel 308-redirects — canonicals referenced redirecting URLs; sitemap listed them.
3. `/from/*` airport pages were indexable while carrying only distance-based flight-time estimates (fails the "real airfare data" gate).
4. Sitemap `lastmod` was stamped with the build date on every deployment.
5. Widget default dates were baked at build time → nondeterministic HTML, breaking CI drift checks and polluting lastmod.
6. Theme page titles auto-appended the current year.
7. Airports rendered as truncated names ("Sangster") instead of "MBJ — Sangster International Airport".
8. Runtime modal injected a second `<h1>` on the homepage.
9. Rows with no structured audience signal defaulted to family-eligible (now `uncertain` → excluded).
10. **Caught by the new validator during this work**: the brand-keyword detector applied to `hotel_brand` misclassified all Beaches resorts (brand "Sandals Resorts International") as adults-only — fixed by splitting policy-phrase matching (name+brand+style) from brand-name matching (property name only), with a regression test.

## Decisions made

- **Rules live in one module** (`scripts/lib/family-rules.mjs`) imported by generator, validator, and tests — rendering and enforcement cannot drift.
- **`uncertain` audience ⇒ excluded** from all family surfaces until verified (5 properties affected; see DATA_QUALITY_AUDIT).
- **All-inclusive = provider-verified only**: the flag is set exclusively from observed live LiteAPI rate offers with AI board type (`sourceType: "provider"`), never from names. Absence of evidence renders "Not confirmed", never "not all-inclusive".
- **/from pages: `noindex, follow`** and out of the sitemap until a real airfare data source feeds them. Content retained for users and internal linking.
- **Canonical host**: `https://kindredtrips.com`, extensionless, lowercase, no trailing slash (matches existing production config; no URL migration needed beyond the `.html` trio).
- **No new indexable page types** until CI gates pass (they now do); generation freeze noted in `family-rules.mjs`.
- **Canonical-entity model**: full CanonicalResort/ProviderListing schema split was intentionally NOT performed in this pass — the DB already enforces one bookable resort per provider ID (unique partial index) and duplicate rows were excluded at source; a schema redesign is tracked as a follow-up (see Remaining risks).

## Remaining risks / external dependencies

- **Booking.com URL verification** needs a network where booking.com is reachable (`scripts/qa-booking-links.mjs`).
- **Origin-airport pages** stay noindexed until a live/cached airfare source exists (needs production flight-data feed).
- **Search Console** submission and Core Web Vitals/CrUX review require account access (manual steps documented in the PR thread).
- **Lighthouse CI**: not wired — the sandbox lacks a Chrome-stable harness for reliable budgets; recommended as a follow-up using `treosh/lighthouse-ci-action` against a Vercel preview URL.
- **Canonical-entity schema split** (provider listings vs. resort entities) — larger DB refactor; current mitigations documented above.
- 5 `uncertain` properties need manual audience verification to re-enter family surfaces.
